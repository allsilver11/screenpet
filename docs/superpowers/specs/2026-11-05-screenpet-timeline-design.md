# 🕐 최근 한 시간 (내 펫 타임라인) — 설계

내 펫이 지난 한 시간 동안 어디에 얼마나 있었고 무엇을 먹었는지 보여 준다. "민수네 15분, 집에서 놀기 32분, 밥 2번…"

## 결정
- **자리는 셋**: 🎈 집에서 놀기(내 화면 어디든) / 🏠 하우스 / 🐾 ○○네 놀러 감(친구마다 따로, 지금 보이는 이름).
  처음엔 창 위·창 안·앱 이름까지 나눴지만, 화면 안 자리는 몇 초마다 바뀌어 10초 머물러야 칸이 되게 해야 했고
  그래서 갱신이 늦어 보였다 → 셋으로 줄이고 바뀌는 순간 바로 새 칸. 앱 이름·창 제목은 읽지 않는다.
- 하우스에서 나와 문 앞에서 먹고 다시 들어갈 참(`returns_home`)이면 하우스로 센다 (잠깐 나온 걸 놀기로 쪼개지 않는다).
- **먹은 것은 횟수로**: 🍚 밥 / 좋아하는 음식(그때 동물의 것, 예: 🥛 우유) / 🍱 특식 / 🍪 간식 / 💧 물. 먹기는 2.5초뿐이라 시간으로 재지 않는다.
  그릇·직접 주기 둘 다, 실제로 먹은 것만 (`FeedResult::Ate`).
- **잠은 넣지 않는다**: 낮잠이 10~20초라 목록이 잘게 쪼개진다.
- **메모리에만**: 저장하지 않고 친구에게 보내지 않는다. 앱을 끄면 사라진다. 프로토콜 변경 없음.
- 친구 화면에서 다른 친구 화면으로 이어 가는 것은 늘 주인 앱이 다시 보내므로(`forward_visit`) 주인이 지금 어느 친구네인지 안다.
- 창에는 안내 글을 두지 않는다 (앱을 켠 지 얼마인지, 메모리에만 있다는 말 등) — 도움말에만.

## 기록 규칙 (`screenpet_core::timeline`)
- 매 틱 `tick(Option<Place>, real_dt)`. real_dt는 게임 루프의 dt(0.05초로 자름)가 아니라 실제로 흐른 시간.
- 자리를 모를 때(`None`: 화면을 떠났는데 아직 어느 친구인지 모르는 사이)는 앞 칸이 이어진다.
- 틱 사이가 길어도(메뉴가 열려 게임 루프가 멈춤·절전) 그 시간은 지금 자리에 쌓는다. 처음엔 5초 넘는 틈을 비워 두고
  새 칸을 열었더니, Windows에서 메뉴를 여는 동안 루프가 멈춰 같은 자리가 여러 줄로 쪼개졌다.
- 친구가 받지 않아 `visit::QUICK_DECLINE_SECS`(3초) 안에 팅겨 온 방문은 지우고 앞 칸에 붙인다 (거절은 따로 알려 오지 않는다 —
  꽉 찬 화면 판정 `return_means_full`과 같은 기준).
- `WINDOW_SECS`(3600초) 밖의 칸·먹은 것은 버린다. 각각 상한 `MAX_ENTRIES`.

## 연결
- 앱: `src-tauri/src/timeline.rs` `TimelineFx` — 게임 루프가 매 틱 `tick`, 먹을 때 `ate`(바로 보낸다).
  창이 열려 있으면 1초마다 `timeline-state` 이벤트, 첫 로드는 `timeline_state` 커맨드 (창 라벨 `timeline`만).
  메뉴 `🐾 내 펫 ▸ 🕐 최근 한 시간`.
- UI: `ui/timeline.html`·`timeline.js` — "지금: … (N분째)" (초는 보이지 않는다), 한 시간 막대 + 먹은 때 이모지, 먹은 것 횟수, 순서대로 목록 (자리별 합계 목록은 두지 않는다 — 막대와 순서대로로 충분). 창 높이는 웹뷰가 내용을 재서 `timeline_fit`으로 맞춘다 (160~760px, 작업 영역 안).
  시간은 분 단위로 보이고, 막대는 1초마다 자란다.
