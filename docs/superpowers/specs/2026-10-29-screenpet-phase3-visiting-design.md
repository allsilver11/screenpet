# ScreenPet 3 — 같은 네트워크 친구 화면으로 놀러 가기

- 작성일: 2026-10-29
- 선행: 2B (`2026-10-29-screenpet-phase2b-design.md`)
- 사용자 요청 요약: 같은 네트워크의 ScreenPet끼리 서로 찾아 연결해 두면, 컴퓨터를 끄거나 네트워크가 끊기기 전까지 계속 연결. 동물이 부르지 않아도 스스로 친구 화면으로 넘어가고, 친구 화면에서도 스스로 넘어온다.

## 1. 연결

- **서로 찾기**: UDP 브로드캐스트(포트 47321)로 2초마다 `{"app":"screenpet","v":1,"id":<설치 고유 id>,"name":<표시 이름>,"port":<TCP 포트>}`를 보내고 받는다. 6초 동안 소식이 없으면 목록에서 뺀다.
  - 설치 고유 id: 처음 실행 때 만든 랜덤 128비트 값 (config에 저장). 표시 이름: Windows 사용자 이름 (트레이에서 바꾸지 않음, v1). 이름은 64자, id는 128바이트로 자른다/거부한다.
  - 알림은 **힌트일 뿐**이다(인증 없음). 한 id에 대해 들린 주소들을 후보로 모아 두고, 실제 신원은 연결 후 Noise 핸드셰이크로 확인한다. 실패한 후보는 피하고 다른 후보를 시도한다. 발견 목록 64개(친구는 항상 받아들임), id당 후보 8개(같은 출발 IP에서 2개), 출발 IP당 초당 50개로 제한한다. 출발지 표가 가득 차면 가장 오래된 항목을 지운다(닫히지 않음). **친구 id의 알림은 속도 제한과 관계없이 처리**한다(어차피 연결 때 Noise로 확인).
- **신원**: 설치마다 장기 **X25519 정적 키쌍**(OS CSPRNG로 생성, config에 비밀키 저장). 친구는 `{id, 상대 정적 공개키}`로 저장한다 — id는 이름표이고 **신원은 고정(pin)된 공개키**다. 비밀값은 절대 네트워크로 보내지 않는다.
- **연결**: TCP (OS가 고른 포트, 브로드캐스트에 실어 알림). 프레임 = 2바이트 길이 + 내용. 연결마다 먼저 **Noise `Noise_XX_25519_ChaChaPoly_BLAKE2s`** 핸드셰이크(건 쪽이 initiator)를 하고, 그 뒤 모든 메시지는 Noise 전송 메시지(암호화+인증, 내장 nonce로 재전송·끼워넣기 불가) 안의 JSON이다. 2초마다 `ping`, 6초 무응답이면 끊김.
  - 핸드셰이크 뒤 상대가 보낸 `hello.id`의 친구 항목이 있으면 상대 정적 키가 고정된 키와 **정확히 같아야** 친구 연결이다(다르면 끊음). 고정된 키가 다른 id로 오면 끊음. 내가 건 연결은 `hello.id`가 내가 건 id와 같아야 한다.
- **허락(1회, 짝맞추기)**: 트레이 `친구 화면 ▸ <발견된 이름>` → 요청자가 **새로 건 연결에서만** `invite`를 보낸다.
  - **커밋→랜덤→공개**: 요청자는 비밀 랜덤 nonce_i의 커밋 `BLAKE2s(nonce_i)`를 `invite`에 담고, 상대는 자기 랜덤 r_r을 `pair_random`으로 보내고, 요청자가 `pair_reveal`로 nonce_i를 공개한다(상대는 커밋 검증, 틀리면 중단).
  - **SAS 확인**: 양쪽이 `BLAKE2s(핸드셰이크 해시 ‖ nonce_i ‖ r_r)`의 앞 36비트로 **이모지 6개**(64종: 동물·음식·물건)를 만든다. 상대 펫 띠에 "<이름>의 <동물>이 놀러 와도 될까요?" + 이모지 6개 + ✓ ✗, 요청자 쪽에도 같은 이모지 6개 + ✓ ✗를 보여 주고 **두 사람이 이모지가 같은지 확인**한다. 중간자는 두 개의 다른 핸드셰이크를 하게 되고, 커밋 때문에 키를 골라 SAS를 맞출 수도 없다(시도당 2^-36).
  - **양쪽 모두 ✓**를 눌러야(각자 `invite_reply{accepted:true}`) 양쪽이 서로의 정적 공개키를 친구로 고정하고 연결한다. 한쪽이라도 ✗이거나 20초 안에 둘 다 확인하지 않으면 거절.
  - 제한: 처리 중인 받은 초대 4개, `Invited` 알림 1분 10회, 같은 주소의 짝맞추기 1분 3회. 확인 전(친구 아님) 연결은 invite/pair_random/pair_reveal/invite_reply/ping만 주고받을 수 있다.
  - 짝맞추기 상태는 **연결마다** 따로다. 다른 연결이 같은 id를 주장해도(가로채기) 초대를 막지 못한다. 같은 id로 진행 중인 짝맞추기는 한 번에 하나.
  - 20초가 지나거나 한쪽이 ✗하면 그 연결의 짝맞추기는 **끝난 상태(Failed)**가 되고, 이후 도착한 확인(`invite_reply`/`answer_invite`)으로는 절대 친구가 되지 않는다. 고정 직전에도 기한을 다시 확인한다.
- **자동 재연결**: 친구가 발견되면 **양쪽 모두** 자동으로 연결을 건다 (다시 묻지 않음). 두 연결이 생기면 id가 작은 쪽이 건 연결 하나만 남긴다. Noise XX 뒤 상대 정적 키 = 고정된 키, 그리고 상대도 나를 친구로 고정했는지(`hello.friend`)를 확인한다.
  - 친구 id가 다른 키로 답하거나(재설치 등), 상대가 나를 친구로 갖고 있지 않으면(한쪽만 고정됨) `FriendKeyMismatch{id}` 이벤트를 내고(앱은 다시 짝맞추기를 권함) 그 주소/친구로의 재연결을 지수적으로 늦춘다(처음 6초, 최대 5분).
  - 트레이에서 `연결 끊기` → 친구 목록에서 지우고 상대에게 알림(보낸 뒤 쓰기만 닫고 상대가 닫을 때까지 기다림).
- **보안**: 친구(고정된 키와 일치)만 동물 메시지를 주고받는다. 알 수 없는 메시지 종류·복호화 실패·잘못된 프레임은 연결을 끊는다(메시지 최대 65519바이트 = Noise 한도). 동물 상태 외 정보는 보내지 않는다. 같은 네트워크(브로드캐스트가 닿는 범위)에서만 동작한다.
- **가용성(정직하게)**: 인증 전 단계(핸드셰이크+hello)는 합쳐서 3초(또는 연결 무응답 기한 중 짧은 것) 안에 끝나야 한다. 인증 전/낯선 들어오는 연결은 모두 6개, 출발 IP당 2개까지이고, 가득 차면 새 연결을 거절하지 않고 **가장 오래된 것을 내보낸다**. 예전에 친구로 인증된 적 있는 주소에서 온 연결은 이 풀과 따로 주소당 4개를 보장받으므로 낯선 연결 폭주가 친구를 밀어내지 못한다. 인증된 친구 연결 수에는 상한이 없다(친구 수만큼). 남는 한계: 여러 주소를 가진 공격자가 계속 연결을 새로 만들면 **처음 보는 주소**에서의 짝맞추기·첫 연결은 늦어지거나 실패할 수 있다. 양쪽 모두 다시 시작해 서로의 주소를 모르는 친구도 같은 상황에서는 늦어질 수 있다(한쪽이라도 상대를 기억하면 양쪽 모두 연결을 걸므로 그 연결은 통과).
- **개인정보**: Noise XX는 상대에게 내 정적 공개키를 보여 준다. 같은 LAN에서 TCP로 접속하는 누구나 내 공개키(그리고 알림의 id·이름)를 볼 수 있어 같은 설치를 다시 알아볼 수 있다. 공개키로는 아무것도 위조할 수 없지만 추적 가능한 식별자다.
  - 남는 위험: 짝맞추기 때 두 사용자가 SAS를 실제로 비교하지 않으면 중간자를 막지 못한다. 짝맞추기 요청자의 id·이름 자체는 확인되지 않는다(사용자가 판단). 인증 전 연결 슬롯을 계속 채우는 공격자는 새 연결을 지연시킬 수 있다(DoS). 중계(1b)에서도 Noise가 끝에서 끝까지 동작하므로 중계 서버는 암호문만 본다.

## 1b. 인터넷 친구 (중계 서버)

- 같은 망이 아니어도 **중계 서버**를 거쳐 오갈 수 있다. 사용자의 Nginx Proxy Manager(192.168.0.52, 관리 화면 :81) 뒤에 중계 프로그램을 두고 `wss://pet.danni.day` (서브도메인은 사용자가 NPM에서 정함)로 공개한다.
- **중계 프로그램** `screenpet-relay` (같은 저장소의 Rust 바이너리): HTTP/WebSocket 서버 하나. 저장하는 것은 설치 id·비밀 토큰 해시·친구 관계뿐. 메시지 내용은 저장하지 않고 친구끼리 전달만 한다.
  - 처음 접속 때 설치 id + 랜덤 비밀 토큰으로 등록, 이후 같은 토큰으로만 그 id 사용.
  - **친구 코드**: 각 설치는 `ABCD-1234` 같은 8자 코드를 받는다(서버가 발급, 24시간마다 바뀜). 상대 코드를 입력하면 상대에게 허락 요청 → 수락 시 서버에 친구 관계 저장.
  - 제한: 메시지 64KB, 초당 20개, 연결당 친구 50명. 친구 아닌 id로의 전달은 거부.
- **앱 쪽**: 같은 망에서 친구가 보이면 직접 연결(LAN), 아니면 중계로 연결. 친구 id는 같으니 어느 길로 연결되든 같은 친구.
- 트레이 `친구 화면 ▸ 내 친구 코드 보기`(펫 머리 위 띠에 코드 표시, 클릭하면 복사), `친구 코드 입력…`(작은 입력 창).
- 중계 서버 주소는 앱에 기본값으로 넣는다 (`wss://pet.danni.day/ws`). 서버가 없거나 꺼져 있으면 인터넷 친구만 안 될 뿐 나머지는 정상.

## 2. 화면 방향

- 친구마다 내 화면의 **왼쪽 또는 오른쪽 끝**이 연결된다. 첫 친구는 오른쪽, 두 번째는 왼쪽, 그 뒤로는 번갈아. 트레이 `친구 화면 ▸ <이름> ▸ 왼쪽에 / 오른쪽에`로 바꿀 수 있다. 한 끝에 여러 친구가 있으면 넘어갈 때 그중 하나를 랜덤으로.
- 상대 쪽에서는 반대편 끝에서 들어온다 (내 오른쪽 → 친구 왼쪽에서 등장). 상대가 정한 방향과 맞지 않아도 "들어온 쪽 = 집으로 가는 쪽"으로 기억한다.
- 끝 = 모든 모니터를 합친 화면의 가장 왼쪽/오른쪽 바닥(작업표시줄 위) 끝.

## 3. 놀러 가기·돌아오기 (부르지 않아도 스스로)

- **나가기**: 내 동물이 바닥을 걷다가 화면 끝(Wall)에 닿았을 때, 그 끝에 연결된 친구가 있으면 **30%** 확률로 뒤돌지 않고 걸어 나간다 (`Exit` — 창 밖으로 걸어가 사라짐, 1초). 성장·배고픔 기록은 집에 남고, 놀러 간 동안 집 쪽 시간은 그대로 흐른다(배고파질 수 있음).
- **도착**: 친구 화면에서 손님 동물이 들어온 쪽 끝 바닥에서 걸어 들어온다 (`Enter`, 1초). 머리 위에 작은 이름표 "🏠 <주인 이름>".
- **손님 생활**: 손님은 친구 PC에서 평소처럼 걷고·애교·간질이기·던지기·벽 타기를 한다. 배고픔·밥·성장은 하지 않는다(주인 쪽만).
- **돌아가기** (손님 쪽에서 결정):
  - 집 방향 끝(Wall)에 닿으면 50% 확률로 걸어 나가 집으로.
  - 방문 3~6분(랜덤)이 지나면 "집이 그리워짐" — 집 방향으로만 걷고, 끝에 닿으면 반드시 나간다.
  - 주인이 트레이 `집에 와`를 누르면 손님은 즉시 손 흔들기(1초) 후 사라지고 주인 화면 끝에서 등장.
  - 손님이 다른 끝(집 방향이 아닌 쪽)에 닿으면 평소처럼 뒤돈다 (v1에서는 친구의 친구로 이어서 가지 않음).
- **돌아옴**: 주인 화면에서 동물이 나갔던 끝에서 걸어 들어온다.
- **끊김**: 연결이 끊기면 손님은 상대 화면에서 손 흔들고 사라지고, 주인 화면에는 원래 동물이 즉시 (나갔던 끝에서) 돌아온다.
- **동시성**: 한 PC에 내 동물 1마리 + 손님 여러 마리(친구 수만큼)가 동시에 있을 수 있다. 각자 별도 창.

## 4. 메시지 (Noise 전송 메시지 안의 JSON, `type` 필드)

| type | 방향 | 내용 |
|---|---|---|
| `hello` | 연결 직후 양쪽 | id, name, v |
| `invite` | 요청자 → 상대 (요청자가 건 연결에서만) | pet, commit = hex BLAKE2s(nonce_i) |
| `pair_random` | 상대 → 요청자 | random = hex r_r (32바이트) |
| `pair_reveal` | 요청자 → 상대 | nonce = hex nonce_i (커밋과 맞아야 함) |
| `invite_reply` | 양쪽 (SAS 표시 후) | accepted — 양쪽 모두 true여야 친구 |
| `visit` | 주인 → 친구 | visit_id, species id, stage, size_mult 적용 크기 배율, personality, owner name, enter_side |
| `leave` | 친구 → 주인 | visit_id (손님이 걸어 나감 → 주인 쪽 등장) |
| `come_home` | 주인 → 친구 | visit_id (즉시 귀가 요청) |
| `unfriend` | 양쪽 | — |
| `ping` | 양쪽 | — |

## 5. 화면 (Tauri)

- 펫 창을 여러 개 다룬다: 내 동물 창 `pet`, 손님 창 `guest-<visit_id>`. 각 창의 웹뷰는 URL 쿼리(`index.html?role=guest&pet=cat&stage=child&owner=...`) 또는 초기화 커맨드로 자기 동물·단계를 안다. 이벤트는 창별로 보낸다(`emit_to`).
- 손님 창: 이름표 띠, 음식 고르기·트레이 돌보기 대상 아님, 우클릭 메뉴는 "<주인>에게 돌려보내기"만.
- 트레이: `친구 화면 ▸` [발견된 사람들(친구 아님) → 클릭 시 초대] / [친구별 ▸ 왼쪽에·오른쪽에 / 연결 끊기], `집에 와` (내 동물이 놀러 가 있을 때만 활성).
- Windows 방화벽: 처음 실행 때 허용 창이 뜬다. 허용하지 않으면 친구 찾기만 안 될 뿐 나머지는 정상.

## 6. 테스트

- 네트워크 모듈: localhost에서 두 인스턴스(다른 포트, 브로드캐스트 대신 지정 주소) — 발견, 초대·수락·거절, 친구 자동 재연결, ping 끊김 감지, 잘못된 메시지 거부, 64KB 제한.
- core: 화면 끝에서 나가기 확률·Exit 연출, Enter 등장, 손님 귀가 규칙(집 방향 50%, 그리움 3~6분, come_home), 끊김 시 즉시 귀환.
- 앱: 여러 창 생성·제거, 창별 이벤트. (실제 두 PC 테스트는 수동 — README 체크리스트.)
