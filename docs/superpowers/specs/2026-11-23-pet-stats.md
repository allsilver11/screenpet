# 📊 펫 선호도 통계 (2026-11-23 요청)

사용자: "친구들의 캐릭터 선호도를 알고 싶어. 캐릭터 선택하는 거, 변경하는 거 수집해서 하루치씩."

## 정한 것

- **동의**: 업데이트 뒤 처음 켤 때 한 번 묻는 창 — "익명 펫 통계를 보낼까요? (키우는 펫 종류와 바꾼 횟수만, 하루에 한 번)"
  [보낼게요] [안 보낼래요]. 창에 왜 모으는지 설명을 꼭 넣음 (사용자 요청):
  "어떤 펫이 인기 있는지 알아보고, 새 펫을 만들 때 참고하려고 모아요. 누가 무엇을 골랐는지는 남지 않아요." 답은 설정에 남고 ⚙️ 설정의 "📊 익명 통계 보내기" 체크로 언제든 바꿈. 답하기 전엔 안 보냄.
- **보는 곳**: 개발자 키가 있는 컴퓨터에만 생기는 "📊 펫 통계" 창 (📬 편지함처럼). 날짜별 종류마다 키우는 사람 수 · 새로 고른 수 · 바꾼 수, 기간 합계와 막대그래프.

## 무엇을 보내나 (하루 한 번, 그날 처음 릴레이에 붙었을 때 — 지난날 것)

- 그날 키운 펫 종류들 (펫 여러 마리면 각각), 그날 새로 고른 종류 (추가·처음), 바꾼 것 (from → to) 수.
- 앱 버전. 이름·설치 id·친구 목록·창 제목은 보내지 않음.

## 서버 (릴레이)

- 하루 단위 합계만 저장 (`stats.json`, 임시 파일 → fsync → rename 규칙).
  - 구현 때 고침 (2026-11-23): 날짜는 UTC가 아니라 **보고하는 앱의 지역 날짜** (그날 쓴 것 그대로 — 받은 때의 UTC 날로 묶으면 한국은 오후 3시에 날이 갈림). 릴레이는 UTC 오늘 ~ 사흘 전 날짜만 받음 (UTC-12 지역 + 이틀 늦게 켠 날).
  - 리뷰 뒤 고침: `.bak` 없음, 5분마다 한꺼번에 저장 (두 파일 비교로 보고 하나를 떼어 보지 못하게). 그날 보낸 설치 표시는 그날 비밀로 만든 해시로 **메모리에만** (파일에 없음, 다시 켜면 잊음). 하루 합계는 쪽으로 나눠 줌 (앱 메시지 64 KiB 한도).
- 같은 설치가 같은 날 두 번 보내 부풀리지 않게: 그날 보낸 설치의 키 해시만 그날 동안 메모리/파일에 두고 다음 날 지움 (합계에는 누가 보냈는지 안 남음).
- 하루 보고 크기·종류 수 상한, 모르는 종류 이름은 "other"로 (아무 글자나 쌓이지 않게), 연결당 하루 1번.
- 90일 지난 날짜는 지움.
- 개발자만 읽음: 편지함과 같은 개발자 서명 인증으로 "통계 주세요" 요청.
- 릴레이를 새로 배포해야 함 (배포는 사용자 확인 뒤).

## 테스트

- 앱 코어: 하루치 모으기 (고르기·바꾸기·여러 마리), 날짜가 바뀌면 지난날 보고를 만듦, 동의 전엔 안 만듦.
- 릴레이: 합계 더하기, 같은 설치 같은 날 두 번 무시, 상한·이상한 이름, 90일 지우기, 개발자 아닌 요청 거절.
- 앱: 소스 검사 (처음 묻는 창, 설정 체크, 개발자 창).
