# 💌 건의하기 / 📬 편지함 (v0.6.0)

누구나 (친구가 아니어도) 자기 펫에게 편지를 들려 개발자에게 보낸다. 받는 쪽(편지함)은 개발자만 있다. 지금은 받기만 한다 (답장 없음).

## 1. 큰 그림

```
보내는 앱 ──(봉한 편지: Noise N, 개발자 공개키)──▶ 릴레이 letters.json ◀──(편지함 읽기: 등록된 설치 키만)── 개발자 앱 (개발자 비밀키로 연다)
```

- **봉하기:** `Noise_N_25519_ChaChaPoly_BLAKE2s` 한 메시지. 받는 사람 정적 키 = 개발자 공개키 (`DEV_KEY`, 앱에 박힌 상수). 릴레이와 다른 사람은 열 수 없다.
- **릴레이:** 봉한 덩어리(불투명)만 저장하고 제한을 건다. 내용은 모른다.
- **읽기 권한:** 릴레이 `control.json`의 `mailbox_readers`(설치 키 목록)에 있는 설치만 편지함을 받는다. 운영자가 `screenpet-relay admin mailbox-reader add|remove <key>`로 정한다 (개발자의 두 컴퓨터).
- **열기:** 개발자 비밀키는 개발자 컴퓨터의 `config.json` `dev_key`(hex)에만 있다. 있으면 📬 메뉴가 생기고, 그 키로 편지를 연다. 연결된 내 다른 컴퓨터에도 같은 `dev_key`를 손으로 넣는다 (설정 파일 공유는 하지 않는다).

## 2. 편지 내용 (봉한 안쪽, JSON)

| 칸 | 뜻 |
|---|---|
| `text` | 본문, 다듬은 글자 1~1000자 (`clean_text`) |
| `name` | 보내는 사람 이름 (친구에게 보이는 이름, 없으면 "") |
| `species`, `stage`, `style` | 보낸 펫 (편지를 들고 오는 손님 모습) |
| `version`, `os` | 앱 버전, `windows`/`macos` |

IP·이메일·친구 목록은 넣지 않는다. 받는 쪽은 모든 칸을 다듬고(길이·알 수 없는 펫은 고양이로), 못 읽으면 "열 수 없는 편지"로 보인다.

## 3. 릴레이

### 메시지 (텍스트 프레임, 기존 `t` 태그 JSON에 더함)

```
client -> relay  letter {box: base64}               -> letter_ok | letter_refused {reason}
client -> relay  letters {}                          -> letters {items: [{id, at, from, read, box}]}   (readers만)
relay  -> client letter_new {item}                   (readers 중 온라인에게, 새 편지가 오면)
client -> relay  letter_read {id} / letter_delete {id} / letter_block {from}   -> letters_changed (readers 모두에게)
```

- `reason`: `daily`(이 키 오늘 이미) · `ip`(이 주소 오늘 3통) · `new`(처음 본 날) · `global`(전체 오늘 50통) · `full`(200통) · `size`(너무 큼) · `blocked`.
- 읽기 권한 없는 설치가 `letters`·`letter_read`·`letter_delete`·`letter_block`을 보내면 무시 (오류로 끊지 않는다).
- 옛 릴레이는 모르는 `t`를 받으면 오류를 보낸다 → 그래서 **릴레이를 먼저 올린다**. 앱은 `letter`에 10초 안에 답이 없으면 "서버에 연결되지 않았어요".

### 제한 (모두 릴레이에서)

| 제한 | 값 | 기준 |
|---|---|---|
| 같은 설치 키 | 하루(24시간 이동 창) 1통 | 인증된 정적 키 |
| 같은 주소 | 하루 3통 | 기존 IP 버킷 (IPv4 / IPv6 /64) |
| 새 키 | 본 날 2일 이상 | `seen_days >= 2` |
| 전체 | 하루 50통 | |
| 편지함 | 200통, 차면 새 편지 거절 | 오래된 것을 지우지 않는다 |
| 크기 | 봉한 덩어리 8 KiB | |
| 차단 | `letter_block`한 키는 거절, 그 키의 편지도 지움 | `mailbox_blocked` |

보낸 기록(키·주소 버킷·시각)은 24시간 지난 것을 버린다.

### 저장

`letters.json` (데이터 폴더, 0600, `relay.json`처럼 `.bak`과 함께 원자 저장): `{next_id, letters: [{id, at, from, read, box}], sent: [{key, ip, at}], blocked: [key]}`. 찢어진 파일은 `.bak`, 그것도 없으면 빈 편지함 (편지는 잃어도 서비스는 선다).

## 4. 앱 — 보내는 쪽 (모두)

- 트레이 메뉴 맨 아래 위: **💌 개발자에게 건의하기…** → 작은 창 (`ui/feedback.html`): 글 상자, 남은 글자 수 (1000), [보내기].
- 보내기 → 네트워크 스레드가 봉해서 `letter` 전송 → 결과를 창에 한 줄로:
  - 성공 "보냈어요 💌 고마워요!" (창은 2초 뒤 닫힘), `daily` "오늘은 이미 보냈어요 — 내일 또 보내 주세요", `new` "앱을 쓴 지 하루가 지나야 보낼 수 있어요", `ip`/`global` "오늘은 편지가 많이 왔어요 — 내일 보내 주세요", `full` "편지함이 꽉 찼어요 — 나중에 보내 주세요", `size` "너무 길어요", `blocked`/연결 없음 "지금은 보낼 수 없어요".
- 성공하면 내 펫이 💌을 들고 손 흔들고 poof → 몇 초 뒤 돌아온다 (기존 보내기 연출을 다시 쓴다; 친구 화면으로 가지는 않는다).

## 5. 앱 — 개발자 쪽

- `dev_key`가 있으면 트레이에 **📬 편지함 (n)** (n = 안 읽은 수, 0이면 숫자 없음).
- 편지함 창 (`ui/mailbox.html`): 최신순, 줄마다 날짜·이름·펫 이모지·버전/OS·본문, [삭제] [차단]. 안 읽은 편지는 굵게, 열면 `letter_read`.
- **편지를 든 펫:** 새 편지(`letter_new`)가 오면, 그리고 앱을 켤 때 안 읽은 편지 중 최근 3통까지 (하나씩, 30초 간격), 보낸 사람 펫이 💌을 들고 화면 끝에서 걸어 들어온다. 네트워크 연결이 없는 로컬 손님이다 (이름표 "💌 <name>"). 누르면 편지함 창이 그 편지를 연다. 60초 뒤(또는 읽으면) 손 흔들고 poof.
- 집중·하우스 중이면 손님은 오지 않고 편지함 숫자만 오른다.

## 6. 호환·배포

- 옛 앱: 메뉴가 없을 뿐, 친구와 노는 건 그대로. 프로토콜 v3 친구 메시지는 바꾸지 않는다.
- 순서: 릴레이 새 바이너리 배포 (`systemctl --user restart screenpet-relay`, 몇 초 끊김) → `mailbox-reader add` 두 키 → 앱 릴리즈.
- `DEV_KEY`(공개키)는 이번에 새로 만든다. 비밀키는 개발자 `config.json`에만 두고 저장소에는 넣지 않는다.

## 7. 테스트

- 릴레이: 제한 7가지 각각, 24시간 지나면 다시 됨, 읽기 권한 없는 요청 무시, `letter_new` 전달, 읽음·삭제·차단이 readers 모두에게, 재시작 후 그대로, 찢어진 파일 복구.
- 네트워크: 봉하기→열기 왕복, 다른 키로는 못 엶, 망가진 덩어리는 None, 편지 JSON 다듬기.
- 앱(Python UI 테스트 패턴): 메뉴가 `dev_key` 있을 때만, 거절 이유 문구, 글자 수 제한, 편지함 창 렌더링·버튼.
- 코어: 편지 손님 상태(들어오기 → 머물기 → poof), 집중·하우스 중엔 안 옴.

## 8. 📮 건의함 (2026-11-12, v0.6.3, 릴레이 프로토콜 v3)

- **트레이 한 항목 "📮 건의함"** (💌 건의하기 바로 밑, 누구나). 개발자 컴퓨터(dev_key)에서는 개발자 건의함(예전 "📬 편지함" — 이름만 바뀜, 안 읽은 수는 "📮 건의함 (n)"), 다른 컴퓨터에서는 읽기 전용 공개 목록(board.html).
- **공개 요약은 개발자 앱이 만든다**: 연 편지마다 `{id, name: 첫 그래핌 + 나머지 그래핌마다 *, line: 첫 줄 60자 + …}` (`screenpet_net::board`). 목록을 받을 때마다(그리고 새 편지가 오면) 릴레이가 `letters.board`로 알려 준 것에 없는 것만 `board_put`. 본문은 개발자 컴퓨터를 떠나지 않는다.
- **릴레이**: 읽는 설치만 올린다. 다시 검사 (가면이 진짜 가면인지, 이름 ≤16자, 줄 1–80자, 제어·방향 문자 제거, 편지가 있는지). `letters.json`에 편지와 함께 — 지우기·막기면 같이 사라진다. `board_list {page}` → 5개씩 최신순, 날짜·상태, 연결마다 0.5초에 한 번.
- **상태 셋**: 없음 · ✅ 반영됨(done) · 🙅 반려됨(rejected), 하나만. `letter_reject {id, rejected}`(v3), 옛 앱의 `letter_done false`는 둘 다 지운다. 옛 파일의 done:true는 반영됨.
- **두 창 같은 쪽 넘기기** (`ui/pager.js`, `ui/list.css`): 5개씩, "‹ 이전 n / m 다음 ›". 개발자 건의함은 읽기·지우기·막기 뒤에도 보던 쪽, 비면 한 쪽 앞.
- **건의는 하루 5통** (보낸 사람 열쇠마다, 24시간 창). 주소당 한도는 10통으로 (한 사람의 5통이 막히지 않게). 6통째: "건의는 하루에 5통까지 보낼 수 있어요".
- 건의하기 창 안내: "보낸 편지의 첫 줄과 이름 첫 글자는 📮 건의함에서 다른 사용자에게도 보여요."
