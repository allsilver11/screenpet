# ScreenPet — 친구들과 사다리타기

- 작성일: 2026-11-04
- 선행: 3 (`2026-10-29-screenpet-phase3-visiting-design.md`) — 친구 연결(Noise), 중계, SAS 이모지
- 사용자 요청 요약: 친구들을 초대해 사다리타기 미니게임. **공정성이 중요 — 완전한 랜덤**. 모든 참가자가 같은 결과를 본다. 펫에 이름표(같은 동물이 여럿일 수 있음), 펫은 종류 상관없이 **baby로 고정**. 방장 포함 **10명까지**. 집중 중·하우스 안이면 **기존 규칙대로 거절** (전체 화면이라고 따로 거절하지 않음).
- 선행 권장: **자동 업데이트** (별도 spec). 이 기능은 참가자 모두가 새 판이어야 하므로(§4), 자동 업데이트 없이 내면 오랫동안 대부분의 친구가 "(업데이트 필요)"로 보인다.

## 1. 놀이 흐름

- 메뉴·창 글자의 사다리 표시는 🎲를 쓴다 (🪜는 Emoji 13.0이라 Windows 10 이모지 글꼴에 없어 네모로 보인다).

1. **방장**: 트레이 `친구랑 놀기 ▸ 🎲 사다리타기…` → 설정 창. 연결된(●) 친구 중 참가자를 고르고(최대 9명), 결과 칸을 적는다.
   - 결과 칸 수 = 참가자 수(방장 포함). 칸마다 글자(12자까지)와 **기분**(😀 좋음 / 😢 나쁨 / 없음)을 정한다. 미리 채우기: "당첨 😀 k개 + 꽝 😢 나머지"(k 기본 1) 또는 직접 입력.
   - 이 기능을 모르는 예전 판 친구는 목록에 흐리게 "(업데이트 필요)"로 보이고 고를 수 없다 (§4).
   - (처음 설계의 `알려 주기`는 뺐다 — 예전 판은 모르는 `ask`를 무시하므로 받는 쪽에 아무것도 보이지 않는다. 최종 리뷰 2026-11-04)
2. **초대**: 고른 친구 화면 주 모니터 가운데에 작은 창 "🎲 <방장>의 사다리타기 — 참가할래요?" + 초대 인원 + 결과 칸 목록 + "참가 인원에 따라 결과 칸이 줄어들 수 있어요" + "참가하면 다른 참가자에게 내 이름과 동물이 보여요" + `참가` `안 할래요`. 30초 안에 답이 없으면 불참.
   - 초대 창은 **포커스를 가져가지 않는다** (작업 중인 키 입력을 뺏지 않음). 답은 클릭으로만 한다 (Enter·Space로 누르지 않음).
   - 메뉴 `사다리 초대 받기` (체크, 기본 켜짐)를 끄면 창 없이 자동으로 `no`.
3. **잠그기**: 모두 답했거나 방장이 `시작`을 누르면(참가 확정 1명 이상) 참가자·결과 칸이 **잠긴다**. 그 뒤로는 아무것도 바꿀 수 없다.
   - 결과 칸 수는 잠글 때 **참가 확정 인원 + 방장**과 같아야 한다. 거절·30초 무응답으로 인원이 줄면 (사용자 결정 2026-11-04):
     - 미리 채우기("당첨 k개 + 꽝")면 인원에 맞춰 자동으로 다시 만든다 — 당첨 수는 그대로, 꽝만 준다 (당첨 수가 인원보다 많으면 인원만큼).
     - 직접 적은 칸이면 "칸이 n개 많아요 — 지울 칸을 골라 주세요"를 띄우고 칸마다 ✕를 보인다. 칸 수가 맞을 때까지 `시작`이 잠긴다 (방장이 적은 결과가 몰래 사라지지 않게). 자동으로 지우지 않는다.
     - 모두 답했어도 칸 수가 맞지 않으면 저절로 잠그지 않는다.
4. **공개**: 모든 참가자 앱이 숨겨 둔 난수를 자동으로 공개하면 사다리가 정해진다 (§3). 참가자 모두의 화면에 같은 사다리 창이 뜬다.
5. **진행**: 위 칸마다 참가자 펫(아기 모습 + 이름표)이 서 있다. 가로줄은 처음에 가려져 있고, 펫이 한 마리씩 내려가며 지나간 길만 드러난다 (`모두 한꺼번에` 버튼으로 동시에 — 각자 화면에서만).
   - 세로줄: 미끄러져 내려간다 (`fall`, 벽 타는 동물은 `slide`). 가로줄: 옆으로 걷는다 (`walk`, 좌우 반전).
   - 결과 칸에 닿으면 그 칸 글자가 펼쳐지고, 기분 😀은 `level_up` 만세, 😢은 `annoyed`, 없음은 `sit_front`.
   - 게임 화면이 뜨고 1.5초가 지나면 방장 신호(`ladder_start`) 없이도 각자 시작한다 — 방장이 그사이 끊겨도 멈추지 않는다.
6. **끝**: 결과 표(이름 → 결과 전체 글자)와 **공정성 지문**(이모지 4개, §3.3)을 보여 준다. 창은 사용자가 닫는다.
   - `결과 복사`: "🎲 <방장>의 사다리타기 · 지문 🐱🍎🎈🌙 / 이름 → 결과 …" 여러 줄을 클립보드에 복사한다 (`code.js`의 `copyText` 재사용). 채팅방에 붙여 넣으면 지문도 자연스럽게 비교된다.
   - 트레이 `🎲 지난 사다리 결과`에서 **가장 최근 한 판**의 결과 표를 다시 열 수 있다 (설정에 저장, 앱 재시작 뒤에도).
   - 내 진짜 펫도 결과 기분에 반응한다 (좋음 = 만세 `level_up`, 나쁨 = 갸웃 `tilt` + 결과 글자 말풍선, 한 번 — `annoyed`는 끝나면 잠드는 상태라 진짜 펫에는 쓰지 않는다). 하우스 안·놀러 가 있음·들림·먹는 중 등이면 건너뛴다.

## 2. 화면에 보이는 펫

- 사다리 창 **안에 그린다** (실제 펫 창·손님 슬롯을 쓰지 않는다 — 손님 10마리 한도, 방문 규칙과 무관). 그림은 각자의 동물 `sheet_baby.png` + 주인이 고른 스타일(동글/픽셀, 픽셀 그림이 없으면 동글). 받는 쪽이 모르는 동물 id면 고양이로 그린다.
- **모두 baby**: 크기가 같아 10칸에 고르게 들어가고, 누가 어른이든 공평해 보인다.
- **이름표**: 펫 머리 위. 내 것은 "나". 별명은 **누가 어느 친구인지 아는 경우에만** 쓴다 (설치 id를 보내지 않으므로 — §3.2): 방장 화면은 모든 참가자에게 방장의 별명, 참가자 화면은 방장에게만 내 별명. 나머지는 잠그기 메시지의 이름(참가자가 스스로 알린 이름). 같은 표시 이름이 둘 이상이면 뒤에 " ②" 같은 번호를 붙인다. 이름표는 홀짝 칸이 두 줄로 엇갈려 두 칸 폭까지 쓰고, 칸 너비에 맞춰 2~6자 + "…"로 줄인다. 글자는 `textContent`로만 쓴다.
- **결과 칸**: 칸 아래에 6자 + "…"까지 (두 줄 허용), 전체 글자는 결과 표에서.
- 창 크기: 칸 너비 72px × 참가자 수 (최소 4칸 폭) + 좌우 여백 60px, 높이 540px. 주 모니터 작업 영역보다 넓으면 칸 너비를 줄인다 (최소 48px). 주 모니터 가운데 (`pair.html`과 같은 자리 잡기).

## 3. 공정성 (완전한 랜덤)

목표: **방장을 포함해 누구도 결과를 미리 알거나 고를 수 없고**, 방장이 참가자마다 다른 결과를 보여 주면 들킬 수 있게 한다.

### 3.1 결과는 사다리가 아니라 순열에서 나온다
- 손으로 그리는 사다리(가로줄을 무작위로 몇 개 긋기)는 **공정하지 않다**. 가까운 칸으로 갈 확률이 높다.
- 그래서 먼저 시드로 **균등 무작위 순열** π(위 칸 i → 결과 칸 π(i))를 뽑고, 그 순열이 되도록 사다리를 **나중에 그린다**: 홀짝 전치 정렬(odd-even transposition sort)로 줄마다 서로 이웃하지 않는 가로줄을 만들고, 결과를 바꾸지 않는 장식 가로줄 쌍(같은 자리에 연달아 두 줄 — 서로 상쇄)을 섞어 최소 8줄 높이로 채운다.
- 위 칸 순서: 참가자 **토큰** 순 (§3.2, 순열이 균등하니 자리는 상관없다).

### 3.2 시드 만들기 — 커밋 → 잠그기 → 공개
연결은 방장과 참가자 사이 1:1뿐이다 (참가자끼리 친구가 아닐 수 있다). 그래서 방장이 가운데서 모아 다시 뿌리는 별 모양이다.

1. 참가할 때 각자(방장 포함) OS CSPRNG로 비밀 32바이트 난수 `n_j`와 **이 판에서만 쓰는 16바이트 토큰** `t_j`를 만든다. 커밋 `c_j = BLAKE2s("screenpet-ladder-commit-v1" ‖ game_id ‖ t_j ‖ n_j)`와 `t_j`, 자기 이름·동물·스타일만 방장에게 보낸다. **설치 id는 다른 참가자에게 절대 보내지 않는다** (참가자끼리 친구가 아닐 수 있다 — 추적 가능한 식별자와 친구 관계가 새지 않게).
2. 방장이 **잠그기**: 참가자 목록(토큰·이름·동물·스타일·커밋)·결과 칸(글자·기분)·game_id를 모두에게 보낸다. 받은 쪽은 자기 토큰·커밋이 그대로 들어 있는지, 토큰이 서로 다른지, 참가자 수 = 결과 칸 수인지, 2~10명인지 확인한다 (아니면 취소).
3. 잠그기를 받은 뒤에만 각자 `n_j`를 방장에게 공개한다 (앱이 자동으로). 방장은 커밋과 맞춰 보고 자기 것까지 모아 모두에게 보낸다. 각자 **모든** 공개값을 커밋과 다시 맞춰 본다 (하나라도 틀리면 취소).
4. 시드 `= BLAKE2s("screenpet-ladder-seed-v1" ‖ L ‖ n_1 ‖ … ‖ n_k)` (토큰 순서). `L` = **잠그기 내용의 고정 바이너리 인코딩의 해시** — JSON 바이트를 해시하지 않는다 (필드 순서·공백·숫자 표기가 판마다·직렬화마다 달라질 수 있어 정직한 참가자끼리도 시드가 어긋난다):
   - `L = BLAKE2s("screenpet-ladder-lock-v1" ‖ game_id(16) ‖ u8 k ‖ u8 방장 자리 ‖ [t_j(16) ‖ c_j(32) ‖ str(name) ‖ str(pet) ‖ str(style)]×k ‖ [str(결과 글자) ‖ str(기분)]×k)`, `str(s)` = u16 LE 바이트 길이 ‖ UTF-8, 참가자는 토큰 순, 스타일은 동글이면 빈 문자열. 기분도 받은 문자열 그대로 넣는다 (나중 판에 기분 종류가 늘어도 판끼리 해시가 같다).
   - 받은 문자열은 **다듬거나 자르지 않는다**: 규칙(앞뒤 공백 없음·제어 문자 없음·글자 수)에 안 맞으면 그 판을 취소한다. 판마다 다듬는 규칙이 달라지면 해시가 어긋나기 때문이다.
5. 순열·사다리는 시드에서 **버전 고정 알고리즘**으로 만든다: 난수열 = `BLAKE2s(seed ‖ 카운터 u32 LE)`를 이어 붙인 바이트, 정수는 거부 샘플링(나머지 연산 치우침 없음), 순열은 Fisher–Yates. **`fastrand`는 쓰지 않는다** (판마다 구현이 바뀌면 참가자끼리 결과가 달라진다).

왜 공정한가:
- 시드에는 모든 참가자의 난수가 들어간다. 자기 난수를 정직하게 만든 참가자가 한 명이라도 있으면 시드는 아무도 예측할 수 없다.
- 커밋을 잠근 뒤에 공개하므로, 남의 난수를 보고 내 난수를 고를 수 없다 (방장도 마찬가지).
- 결과 칸(글자·기분)도 잠그기에 들어가 있으므로, 결과를 본 뒤 칸을 바꿀 수 없다.

### 3.3 공정성 지문
- 방장은 참가자마다 다른 목록을 보낼 수도 있다(이중 플레이). 그러면 화면마다 시드가 달라진다.
- 모든 화면에 `BLAKE2s("screenpet-ladder-print-v1" ‖ seed)`의 앞 24비트로 만든 **이모지 4개**(`noise::SAS_EMOJI` 64종)를 보여 준다: "모두의 이모지가 같으면 공정한 게임이에요".
- 친구 맺기 SAS와 달리 **비교를 강제하지 않는다**. 이건 방장 조작을 막는 장치가 아니라 의심될 때 확인하는 도구다. `결과 복사`에 지문이 들어가 채팅방에서 자연스럽게 비교된다.

### 3.4 정직하게 남는 한계
- **공개를 안 하고 버티기**: 공개는 앱이 자동으로 하므로, 조작한 앱이 아니면 일부러 버틸 수 없다. 공개가 안 오는 건 대개 네트워크 끊김·절전이다. 다만 방장은 모든 공개값을 먼저 모으니, 조작한 앱이라면 결과를 계산해 보고 뿌리지 않을 수 있다. 이건 막을 수 없고 **드러나게만** 한다: 공개 15초 기한이 지나면 취소하고 **중립적으로** "<이름>과 연결이 끊겨 취소됐어요" / "방장에게서 결과가 오지 않아 취소됐어요"를 보여 준다 (누가 일부러 그랬다고 탓하지 않는다).
- **다시 하기**: 방장은 결과가 마음에 안 들면 취소하고 새 판을 열 수 있다. 같은 game_id는 다시 쓰지 않으므로(새 판 = 새 난수) 결과를 고를 수는 없지만, 원하는 결과가 나올 때까지 반복할 수는 있다. 취소된 판은 모두에게 보이므로 사회적으로만 드러난다.
- 참가자 이름은 각자 스스로 알린 이름을 방장이 전달한 값이다 (참가자끼리 친구가 아니면 확인할 길이 없음). 지문은 참가 목록 전체를 덮으므로, 이름을 바꿔치기하면 지문이 달라진다.

## 4. 메시지와 버전

- 앱 프로토콜 `screenpet_net::protocol::PROTOCOL_VERSION`을 **1 → 2**로 올리고, `peers`가 상대 `hello.v`를 친구 연결마다 저장하고(다시 보낸 hello로 갱신) `Net::peer_version`으로 알려 준다. 지금까지는 `v`를 보내기만 하고 읽지 않았고, 모든 판이 1이었다.
  - 중계 서버의 `screenpet_relay::proto::PROTOCOL_VERSION`은 **별개라 건드리지 않는다** (중계는 바뀌지 않음).
- **예전 판에는 사다리 메시지를 절대 보내지 않는다**: 알 수 없는 `type`을 받으면 연결을 끊기 때문이다 (`peers.rs` — `Message::parse` 실패 → `break`). 상대 `v < 2`면 설정 창 목록에서 흐리게 보이고 초대할 수 없다. 보내기 함수도 `v < 2`인 상대에게는 보내지 않고 버린다 (이중 안전장치).
- 새 `Message` 변형 `Ladder(LadderMsg)` (Noise 전송 메시지 안 JSON, `type` 태그):

| type | 방향 | 내용 |
|---|---|---|
| `ladder_invite` | 방장→참가자 | `game_id`(16바이트 hex), 방장 이름, 결과 칸 미리보기 `[{text, mood}]`(최종 칸은 잠그기에서 — 누가 참가하느냐에 따라 칸 수가 바뀐다), 초대 인원 |
| `ladder_join` | 참가자→방장 | `game_id`, `token`, `commit`, `name`, `pet`, `style` |
| `ladder_decline` | 참가자→방장 | `game_id`, `reason: "no" \| "busy" \| "playing"` |
| `ladder_lock` | 방장→참가자 | `game_id`, `host`(참가자 목록 안 방장 자리), 참가자 `[{token, name, pet, style, commit}]`(토큰 순), 결과 칸 `[{text, mood}]` |
| `ladder_reveal` | 참가자→방장 | `game_id`, `nonce` |
| `ladder_reveals` | 방장→참가자 | `game_id`, `[nonce]`(토큰 순, 방장 것 포함) |
| `ladder_start` | 방장→참가자 | `game_id`, `mode: "one_by_one" \| "all"` — 연출 맞추기일 뿐, 결과와 무관. 안 와도 3초 뒤 시작 |
| `ladder_cancel` | 양쪽 | `game_id`, `reason: "host" \| "left" \| "timeout" \| "invalid"`, `who`(토큰, 있으면) |

- 제한: 결과 칸 글자 12자(줄바꿈·탭·제어 문자 없음), 이름 `clamp_name`, 기분 `good \| bad \| none`(모르는 값은 none), 한 설치당 동시에 한 판, 받은 초대는 처리 중 1개(더 오면 `playing`), 같은 친구의 초대 1분 3회(넘으면 조용히 `no`). 범위 밖 값은 메시지째 버리고 그 판을 취소한다 (연결은 끊지 않음).
- 중계(1b)는 바뀌지 않는다 — 암호문만 나른다. 메시지는 10명이어도 수 KB로 Noise 한도(65519바이트) 안이다.

## 5. 거절 규칙 (기존 규칙 그대로)

- 받는 쪽이 **집중 중이거나 펫이 하우스 안**이면(`Pet::refuses_arrivals`) 초대 창을 띄우지 않고 자동으로 `ladder_decline { reason: "busy" }`. 방장 설정 창에 그 친구 옆에 "바빠요"를 표시한다.
- 방장이 집중 중이거나 하우스 안이면 메뉴 `🎲 사다리타기…`가 비활성이다.
- 전체 화면 앱은 따로 거절하지 않는다 (초대 창이 포커스를 가져가지 않으므로 키 입력은 뺏기지 않는다).
- 잠근 뒤에 누가 집중을 시작하거나 하우스에 들어가도 판은 그대로 이어진다 (결과는 이미 정해짐). 그 사람 창에서는 진행 화면을 건너뛰고 결과 표만 보여 준다.
- 내 펫이 친구 화면에 놀러 가 있어도 참가할 수 있다 (사다리 펫은 창 안 그림이다).

## 6. 끊김·시간 초과

| 상황 | 처리 |
|---|---|
| 초대 30초 무응답 | 그 친구는 불참. 그 뒤에 온 참가(늦은 참가)에는 "초대가 끝났어요"(`ladder_cancel host`)로 답한다 |
| 참가했는데 2분 동안 잠그지 않음 | 참가자가 포기하고 방장에게 `ladder_cancel left`를 보낸다 — 방장은 그 사람을 빼고 잠근다 |
| 잠그기 전 참가자 끊김 | 그 참가자만 빠짐 (방장 말고 1명 이상 남으면 계속) |
| 잠근 뒤 공개 전 누구든 끊김 / 공개 15초 초과 | 판 취소, 누구와 끊겼는지 중립적으로 표시 (§3.4) |
| 결과 공개 뒤 끊김 | 상관없음 — 각자 이미 같은 결과를 갖고 있고, 1.5초 뒤 스스로 시작한다 |
| 방장 앱 종료 | 공개 전이면 취소 |

## 7. 코드 위치

- `crates/screenpet-core/src/ladder.rs` (순수): 난수열 → 순열 → 사다리(줄·가로줄), 길 따라가기, 결과 칸 글자 검사, 표시 이름 번호 붙이기, 지문 비트 → 이모지 번호, 창 칸 너비 계산. 난수는 `FnMut() -> u32`로 받는다 (core는 해시를 모른다).
- `crates/screenpet-net/src/ladder.rs`: 커밋·잠그기 인코딩·시드·난수열·지문 해시(`blake2`가 이미 여기 있다), 방장·참가자 **상태 기계** (I/O 없음, `Instant`를 받아 시간 초과 처리 — 리눅스에서 테스트). `protocol.rs` `Ladder` 메시지, `peers.rs` 상대 `v` 저장, `Net::send_ladder`(v < 2면 버림), `NetEvent::Ladder`.
- `crates/screenpet-net/examples/ladder_bot.rs`: QA용 **헤드리스 참가자** (친구 맺기 자동 확인, 초대 자동 참가, 받은 시드·지문 출력). 앱은 한 PC에 하나만 뜨므로(`single-instance`) 봇 없이는 3~10명 판을 시험하기 어렵다.
- `src-tauri/src/ladder.rs`: 상태 기계를 네트워크·창·게임 루프에 잇는다. 창 열기/닫기, 지난 결과 저장. `network.rs`가 `Ladder` 이벤트를 넘겨준다. `tray.rs` 메뉴 항목. `screenpet-core/src/config.rs`: `ladder_invites: bool`(기본 true), `last_ladder: Option<…>`.
- `ui/ladder.html` · `ui/ladder.js`: 설정·초대·게임·결과 화면 (창 하나, 상태로 바꿈). 펫 그림은 `ui/common.js`의 프레임 계산(`frameIndex`, `pixelFrameSize`)을 다시 쓰고, 시트를 칸 크기로 그리는 작은 그리기 함수만 새로 만든다.

## 8. 테스트

- core `ladder`:
  - 2~10명, 시드 수천 개: 사다리 길 따라가기 결과 == π, 한 줄 안에 이웃한 가로줄 없음, 최소 높이.
  - **균등성**: 3명 × 시드 60000개 → 순열 6가지가 카이제곱 검정 통과. 10명은 칸별 도착 분포 검정.
  - **고정 벡터**: 정해진 난수열 → 정해진 순열·사다리 (알고리즘이 바뀌면 깨지게 — 판끼리 결과가 같아야 함).
  - 이름 번호 붙이기, 결과 칸 글자 검사, 칸 너비.
- net:
  - **고정 벡터**: 정해진 잠그기 내용 → 정해진 `L`·시드·지문 (인코딩이 바뀌면 깨지게).
  - 커밋 검증 (틀린 공개값 → 취소), 잠그기에서 내 토큰·커밋이 바뀜 → 취소, 토큰 중복 → 취소, 공개값 순서·개수 오류 → 취소, 시간 초과 → 취소(이유·대상).
  - 잠그기·공개 메시지에 설치 id가 들어 있지 않음.
  - `v = 1` 친구에게는 사다리 메시지를 보내지 않음 (예전 판 흉내 연결이 끊기지 않음). `v = 2` 친구는 `peer_version == Some(2)`.
  - 별 모양 3명 시뮬레이션(localhost Net 세 개): 모두 같은 시드·지문.
- UI 하네스 (`tools/ladder_harness.js` + `tools/test_ladder_ui.py`, 기존 levelup 하네스 방식): 이름표 겹침 없음, 긴 이름·결과 줄임, 결과 표, 결과 복사 글자, 지문 표시.
- README 수동 테스트 체크리스트에 "사다리타기 (PC 두 대 + 봇)" 묶음 추가.
