# Desktop Pets — 설계 문서

- 작성일: 2026-10-28
- 상태: 검토 대기

## 1. 목표

Windows(우선)와 macOS(이후)에서 바탕화면 위를 돌아다니는 귀여운 동물 앱.
동물은 화면 바닥(작업표시줄 위)과 다른 앱 창의 윗라인 위를 걸어 다니며,
마우스로 집어 던지면 포물선을 그리며 날아가 창 윗라인이나 바닥에 착지한다.

### 첫 버전 범위

- 동물 4종: 고양이, 강아지, 토끼, 곰 (phase 2B에서 비버 → 곰) — **한 번에 한 마리** 표시(트레이에서 선택)
- 걷기, 자유 행동(앉기·두리번·잠자기), 클릭 반응(하트 + 점프)
- 드래그 & 던지기, 창 윗라인 착지, 창 타고 가기
- 트레이 메뉴
- Windows 빌드(GitHub Actions)

### 범위 밖 (이후 버전)

- 여러 마리 동시 표시 (구조는 여러 마리를 막지 않게 설계)
- macOS 지원 (`platform/macos.rs` 추가로 대응)
- 코드 서명, 자동 업데이트, 설정 창

### 다음 단계 후보 (첫 버전 개발·테스트 완료 후 별도 설계)

- 동물 디자인 고도화 (AI 생성 스프라이트로 교체, 동작 다양화)
- 돌보기 기능: 배고픔 같은 욕구 표시 → 밥 주기 등 상호작용
- 성장 시스템 (사용자 요청 메모, 2단계에서 상세 설계):
  - 단계: baby → kinder → child → teenager → adult. 처음엔 아주 작은 새끼로 시작해 레벨이 오를수록 조금씩 커짐
  - 동물이 "배고프다" 행동을 하면 사용자가 밥 주기 → 밥 종류 약 3가지 중 선택
  - 밥은 숨겨진 체력 stat을 올림 (화면에 표시하지 않고 설정 파일로만 관리). 레벨별 stat이 꽉 차면 한 단계 성장
  - 레벨 리셋 가능, 레벨 고정 가능 (새끼로 계속 키우고 싶은 경우)
  - 레벨 고정 중에도 배고프다 행동은 계속 하고 밥도 줄 수 있지만, stat 증가·성장은 없음
  - 레벨 고정 시 다른 단계 모습을 미리보기할 수 없음 (성장을 기대하게)
  - 1단계 영향: 스프라이트 크기가 단계별로 달라짐 → `PetConfig.size`·`half_w`를 고정값이 아닌 설정값으로 유지

## 2. 기술 선택

- **Tauri 2** (Rust 백엔드 + 웹뷰 프론트엔드)
- 동물마다 **동물 크기의 작은 투명 창**(항상 위, 테두리 없음, 작업표시줄 미표시)을 띄우고 창 자체를 이동시킨다.
  전체화면 오버레이 + 클릭 통과 방식은 쓰지 않는다.
- 이유: 상시 실행 앱이라 가벼워야 하고(설치 파일 약 5~10MB), OS 의존 코드를 한 모듈로 격리하기 쉽다.
- 사용자 PC에는 별도 런타임 설치가 필요 없다 (Windows 10/11은 WebView2 기본 탑재).

## 3. 전체 구조

```
Rust (Tauri 백엔드)
  game loop (60fps 스레드)
    pet::Brain        상태 머신 — 다음 행동 결정
    physics           중력, 던지기 속도, 벽 반사, 착지 판정
    world::Surfaces   디딜 수 있는 수평 선분 목록 계산
                        - 작업 영역 바닥(작업표시줄 위)
                        - 각 창 윗라인 − 더 앞쪽(Z-order) 창에 가려진 구간
    platform          OS별 창 정보 (trait WindowSource)
                        - windows.rs : EnumWindows + DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)
                        - macos.rs   : CGWindowListCopyWindowInfo   (이후)
                        - fake.rs    : 테스트용
  tray                동물 선택, 숨기기/보이기, 종료
  config              마지막 선택 동물 저장

펫 창 (웹뷰)
  스프라이트 시트에서 현재 프레임만 그림 (좌우 반전 포함)
  마우스 이벤트 → 백엔드로 전달 (누름 / 이동 / 놓음)
```

### 원칙

- **모든 판단은 Rust**에서 한다. 웹뷰는 "현재 동작·프레임·방향"을 받아 그리기만 한다.
- `Brain`, `physics`, `Surfaces`는 OS에 의존하지 않는 순수 로직 → 리눅스에서 `cargo test` 가능.
- OS 의존 코드는 `platform` 모듈에만 둔다.
- 창 목록 조회는 **약 10Hz**, 시뮬레이션은 **60Hz**로 분리한다.

### 창 필터링 (디딤판에서 제외)

펫 창 자신, 보이지 않는 창, 최소화된 창, 클로킹된 창(DWMWA_CLOAKED — 다른 가상 데스크톱 등),
도구 창(WS_EX_TOOLWINDOW), 크기 0 또는 극히 작은 창, 바탕화면/작업표시줄 셸 창.

### 좌표계

모든 모니터를 합친 가상 화면 좌표(물리 픽셀)를 하나의 세계로 쓴다.
펫 창 배치 시 DPI 배율을 반영한다. 바닥은 각 모니터의 작업 영역(work area) 하단이다.

## 4. 디딤판(Surfaces) 계산

1. Z-order 앞쪽부터 창 목록을 순회한다.
2. 각 창의 윗라인 선분 `[left, right] @ y=top`에서, 그보다 앞쪽 창들의 사각형이 덮는 x 구간을 뺀다
   (앞쪽 창 사각형이 `y=top`을 포함할 때 덮는 것으로 본다).
3. 남은 조각마다 `Surface { window_id, y, x_start, x_end }`를 만든다. 
   조각 끝이 "가려짐 때문에 끝났는지(Blocked)" / "창 모서리라서 끝났는지(Edge)"를 양 끝마다 기록한다.
4. 각 모니터 작업 영역 하단을 `Surface { window_id: Ground, ... }`로 추가한다 (양 끝은 화면 벽).

## 5. 상태 머신

```
Walk ⇄ Idle(앉기/두리번) → Sleep
Walk ─ Blocked 끝 도달 ───────────────→ Turn → Walk
Walk ─ Edge 끝 도달 ─ 50% ─────────────→ Turn → Walk
                     └ 50% ─────────────→ Hop
Walk/Idle ─ 서 있는 조각 너비 < 몸 너비 ──→ Hop
서 있는 위치가 덮임 / 창 최소화·닫힘 ────→ Fall(놀람)
마우스 누름+이동 ───────────────────────→ Dragged → (놓음) → Thrown
Fall / Hop / Thrown ─ 착지 ─────────────→ Land → Idle
Walk/Idle/Turn ─ 짧은 클릭 ─────────────→ Happy(하트 + 제자리 점프) → Idle
공중(Fall/Hop/Thrown) ─ 짧은 클릭 ───────→ 잡았다 놓은 것으로 처리 (속도 0으로 Thrown)
Sleep ─ 클릭 ──────────────────────────→ 깨어나서 Idle
```

### 세부 규칙

| 항목 | 값 |
|---|---|
| Walk 지속 | 2~8초 랜덤 후 Idle 또는 방향 전환 |
| Idle 지속 | 3~6초 |
| Sleep 진입 | Idle 종료 시 25% 확률, 15~40초 유지 |
| 걷기 속도 | 동물별 `pet.json`의 `walk_speed` (px/s) |
| Edge 도달 | 50% Turn / 50% Hop |
| Blocked 도달 | 항상 Turn (멈칫 0.3초 후 뒤돌기) |
| 클릭 판정 | 누름~놓음 이동 거리 5px 미만 |
| 던지기 속도 | 놓기 직전 약 100ms 마우스 이동 속도, 최대치 제한 |
| 중력 | 약 2500 px/s² (튜닝) |
| 벽 | 가상 화면 좌우 끝에서 수평 속도 반전(감쇠) |

### 착지 판정

- 낙하 중(수직 속도 > 0, 아래 방향)일 때만 판정한다.
- 이번 프레임 발 위치 이동 구간 `[y_prev, y_now]`이 어떤 Surface의 `y`를 통과하고,
  발 중심 x가 그 Surface 구간 안이면 착지한다. 여러 개면 가장 위(y가 작은) 것.
- 상승 중에는 판정하지 않는다 (창 윗라인을 아래에서 뚫고 올라갈 수 있음).

### 타고 가기

- 서 있는 Surface의 `window_id`와 창 내 상대 x를 기억한다.
- 창 목록 갱신 시 해당 창이 이동했으면 같은 변위만큼 펫을 이동한다.
- 해당 창이 사라졌거나 최소화되었거나, 펫 위치가 더 이상 보이는 조각 안에 없으면 Fall.

## 6. 스프라이트 형식

```
assets/pets/<name>/
  sheet.png
  pet.json
```

- 프레임 64×64px, 화면 표시 2배(128px), 최근접 보간(픽셀아트 선명도 유지).
- 투명 배경, **오른쪽을 보는 방향**으로 그림. 왼쪽은 좌우 반전.
- 시트: 각 줄 = 동작 하나, 가로로 프레임 나열.
- 필수 동작: `walk`, `idle`, `look`, `sleep`, `hop`, `fall`, `dragged`, `land`.

`pet.json` 예시:

```json
{
  "name": "고양이",
  "frame_size": 64,
  "walk_speed": 60,
  "animations": {
    "walk":    { "row": 0, "frames": 4, "fps": 8 },
    "idle":    { "row": 1, "frames": 2, "fps": 2 },
    "look":    { "row": 2, "frames": 4, "fps": 4 },
    "sleep":   { "row": 3, "frames": 2, "fps": 1 },
    "hop":     { "row": 4, "frames": 3, "fps": 10, "loop": false },
    "fall":    { "row": 5, "frames": 2, "fps": 8 },
    "dragged": { "row": 6, "frames": 2, "fps": 4 },
    "land":    { "row": 7, "frames": 2, "fps": 10, "loop": false }
  }
}
```

- 새 동물 = 폴더 하나 추가 (코드 변경 없음). 앱에 번들된 동물 폴더 목록이 트레이 메뉴가 된다.
- **임시 그림**: 스크립트로 단순한 픽셀 동물 4종 시트를 생성해 먼저 사용한다.
- **AI 생성 지원**:
  - `tools/pack_sheet` — 동작별 개별 프레임 PNG를 규격 시트로 합치는 스크립트
  - `docs/sprites.md` — 프레임 간 일관성을 위한 생성 팁과 프롬프트 템플릿

## 7. 트레이 메뉴

- 동물 선택 (라디오: 고양이 / 강아지 / 토끼 / 곰)
- 숨기기 / 보이기
- 종료
- 마지막 선택 동물은 앱 설정 디렉터리의 설정 파일에 저장, 다음 실행 시 복원.

## 8. 오류 처리

- 창 목록 조회 실패 시: 직전 목록 유지, 계속 실패하면 바닥만 사용.
- 스프라이트 로드 실패 시: 해당 동물을 메뉴에서 제외, 하나도 없으면 임시 그림 사용.
- 펫이 화면 밖으로 벗어나면(모니터 분리 등): 가장 가까운 모니터 상단에서 다시 떨어뜨린다.

## 9. 테스트

- **자동 (`cargo test`, 리눅스에서 실행)**: `fake` WindowSource로
  - 디딤판 계산: 가림 구간 빼기, Blocked/Edge 끝 표시
  - 상태 전이: Blocked→Turn, Edge→Turn/Hop(시드 고정 RNG), 좁은 조각→Hop, 발밑 덮임→Fall
  - 착지 판정: 통과 시 착지, 상승 중 미판정, 여러 Surface 중 최상단 선택
  - 타고 가기: 창 이동 시 동반 이동, 창 소멸 시 Fall
  - `pet.json` 파싱 및 검증
- **수동 (Windows 실기)**: 체크리스트 제공 — 창 위 던져 올리기, 창 이동/최소화/닫기,
  가림 구간 뒤돌기, 작업표시줄 위치 변경, 듀얼 모니터, DPI 배율 125%/150%.

## 10. 빌드 & 배포

- GitHub Actions: 태그 push 또는 수동 실행 시 `windows-latest`에서 `tauri-action`으로 `.msi`/`.exe` 생성,
  아티팩트(및 태그 시 Release)로 업로드.
- 모든 push/PR에서 `cargo test` (ubuntu) 실행.
- macOS(`macos-latest`)는 `macos.rs` 구현 시 매트릭스에 추가.
- 코드 서명 없음 → 첫 실행 시 SmartScreen 경고 (개인용은 "추가 정보 → 실행").
- 저장소 주소는 개발 완료 후 사용자에게 받아 push한다.
